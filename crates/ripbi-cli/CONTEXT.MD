# ripbi-cli — CONTEXT

The `ripbi` binary. Thin orchestration layer over `ripbi-core`:
argument parsing (clap), source-format auto-detection dispatch, human-readable and
CI-friendly output, and exit codes.

## Rules

- **No analysis logic here.** All ingestion, lexing, and graph work lives in
  `ripbi-core`; this crate only calls it and presents results.
- This is the only crate allowed to print to stdout/stderr or set exit codes.
- Exit codes: `0` clean, `1` unused objects found, auto date/time machinery no
  report binds, or — only under `--broken` — broken visual bindings or DAX artifacts (issues #60/#84:
  breakage is reported by default but gates only when selected) (CI gating), `2`
  error (usage, discovery, ingestion, or `--strict`
  skip notices). A model with no connected reports refuses with `2` unless
  `--allow-no-reports` skips it: a `Skipped …` notice on stderr, exit `0`, no
  stdout output. `update` reuses the same 0/1/2: `1` only from `--check` when a
  newer release exists; a completed self-update is `0`. `report` is informational:
  `0` for any produced inventory, `2` on error — it never gates on what it lists.
  `deps` shares that contract: `0` for any produced view (empty impact included),
  `2` on usage, discovery, lookup, or analysis error. `report --allow-no-model`
  trades the pairing refusal for a model-less listing (exit `0`); everything
  else it lists is informational and never gates. `fetch` is `0` or `2`: `2` for
  any error and for an incomplete report set nobody accepted (`--allow-incomplete`
  or the prompt); with `--scan`, a fetched folder returns the scan's code.
- Results to stdout; messages, notices, and errors to stderr. `-q` suppresses both.
- `#![forbid(unsafe_code)]`.

## Layout

`src/lib.rs` wires the modules; `main.rs` only parses and maps the returned code to
`ExitCode`. The lib target exists so integration tests drive `scan` and `update`
without spawning a process (`Streams` injects stdout/stderr/stdin and the
stdin/stderr-are-TTY bits; `ReleaseClient` fakes the network).
The short alias `rib` (`src/bin/rib.rs`) shares `entry::run` with `main.rs`; the clap
command name is pinned to `ripbi` (`cli.rs`), so help and `--version` always say
`ripbi`, whichever binary was typed.

| Module | Role |
|---|---|
| `cli.rs` | clap definitions — the user-facing interface. Scan's selection resolves through `selected_kinds` (`--type`, including `bookmark`, validated against `render::KINDS`; `--broken` selects `broken_visual` and `broken_artifact` and is the only breakage gate). Two gates keep the surface consistent: help text stays one line ≤100 chars, and every command with a `--model` flag declares `--model`/`--report` first |
| `config.rs` | `ripbi.toml` discovery (cwd upward), parsing, path resolution; `StatsSetting` is the shared `--stats-from`/`[scan].stats_from` value (`none` or a path); top-level `queries_from` is the query log both `scan` and `deps` read, and `queries_item` picks its model |
| `discover.rs` | PATH classification, PBIP stem pairing, cwd candidate discovery; model target resolution (`.SemanticModel`/`definition/`/`model.tmdl` folders, the `.pbip` naming the project, and model files: `model.bim`, `.abf`, a PBIT/PBIX embedding its model — `is_model_file`; a model-bearing PBIX pairs with itself, a thin one with a sibling model) and bound-report folder walking (byPath → stem → `byConnection` name). Report→model pairing climbs stem sibling → sole `.SemanticModel` sibling → `definition.pbir` `byPath` → `byConnection` dataset name (pairing only when exactly one sibling model's stem or `.platform` display name carries it); a project with no model folder of its own pairs through its stem-named report's reference |
| `entry.rs` | process entry shared by the `ripbi` and `rib` binaries: real stdio → one command → exit code → the update notifier hook |
| `scan.rs` | orchestration: resolve → ingest (core) → graph (core) → ignore filter → type filter → render. Auto date/time verdict rows are assembled here (a dead table's own finding moves under its verdict; the section prints only when no type filter runs without `--type table`). Broken bindings (`graph.broken_bindings`) are bucketed here too: `[scan].ignore` → hidden-by-type-selection → suppressed (model ingest reported `unknown_object` skips — the issue #60 clean-ingest bar: only drift that can hide a name) → reported; gating is `--broken`-only and deliberately distinct from reporting. The zero-connected-report refusal (exit `2`) and the `--allow-no-reports` skip (`Skipped …`, exit `0`) share one detail helper, so both explain the empty walk identically. The pairing announce is capped to one line per fact in every mode (`--verbose` expands it). Also owns `resolve_target` — the one target-resolution entry point `scan`, `report`, and `deps` share (`--model` mode, else PATH/config target plus `--report` anchors, else model derivation from `--report` anchors alone, else cwd discovery); a new command calls it and inherits every input shape. Skip-notice helpers (`dedupe`, `skip_notice_out`, `write_skip_notices`) stay here too. `attach_storage` applies the issue #129 storage source (`--stats-from` > `[scan].stats_from` > `.pbi/cache.abf`) after model ingest and prints its coverage/staleness notes; an explicit source that fails is exit `2`, an auto-detected one only a note. `load_query_log` (shared with `deps`) reads the `--queries-from`/`queries_from` workspace-monitoring export for `DependencyGraph::build_with_queries`: an unreadable log is exit `2`, its size and window are a note; a log covering several models (`ItemName`/`ItemId`) is narrowed to this one (`--queries-item`, else the model's folder/file name) with a note, and counts none of its queries when none matches; that and a single-model log under another name are `stale_state` skip notices (never an exit code, but `--strict` gates on them), and `consumer_hint` rewords the caveat when a log is in play, or to "other Excel workbooks" when a workbook is among the reports (`has_workbooks`). Excel workbooks (issue #172) are direct `--report`/`reports` items only (`is_report_item`), never search-walk finds; `.xls`/`.xlsb` refuse with exit `2` (`binary_workbook_error`), a workbook alone cannot derive the model, and the pairing announce lists the workbooks read |
| `report.rs` + `report/render.rs` | `ripbi report` (issue #33): the report inventory — pages → visuals → fields — as data. Resolves and ingests exactly like `scan`, builds the graph to read `broken_bindings` (attributed to visuals, pages, and the report by name; the same `unknown_object` suppression bar) and reachability (`--used`). Four list views (`--pages`/`--visuals`/`--fields`/`--used`) hand-roll aligned tables via one `write_table` helper; six glob filters (`--page`/`--visual`/`--site`/`--kind`/`--match`/`--broken`) prune the inventory and recompute counts for every mode. Human tree (connected pages and visuals, `filters (n)`/`unresolved (n)` group nodes, per-block label columns), `--plain` typed records, `--json` `schema_version: 1` (contract: `docs/report.md`). `--allow-no-model` inventories a report with no paired model — report-side listing only, `--used`/`--broken` refused; it rescues the typed no-model pairing failures (see `error.rs`) never mistyped paths |
| `deps.rs` + `deps/` | `ripbi deps` (issue #20): dependency and impact exploration. Resolves and ingests exactly like `scan` through the shared target-resolution helpers — **minus the zero-report refusal** (model-only exploration is valid). Analysis stays in core: `DependencyGraph::dependencies_of`/`impact_of` slices + `lookup::resolve_reference` (ambiguity lists candidates, typos offer the nearest match). `deps/tree.rs` projects a slice into the human tree (`↩ already shown`, `↺ cycle`, a fixed expansion budget with an explicit footer); `deps/graph_view.rs` draws the `--graph` topology diagram (BFS layers, barycenter rows, deterministic, degrades past 24 nodes); `deps/render.rs` owns all three output modes — human, `--plain`, `--json` `schema_version: 1` (contract: `docs/deps.md`), which never truncate. The Impact view's `Kept` section (`kept` records / JSON array) names the `ripbi_keep` annotations on the impact slice (`DependencyGraph::kept_by`, issue #151); the consumer and report filters drop it. The `Queried` section after it (`queried` records / JSON array) names the objects `--queries-from` logged queries reference (`DependencyGraph::queried_by`), with counts, never user names; the same filters drop it. Filters (`--consumer`/`--in-report`/`--on-page`) restrict results after full traversal |
| `fetch.rs` + `fetch/` | `ripbi fetch`: the thin CLI over `ripbi-service` (contract: `docs/fetch.md`). `token_source` picks `--auth` (else env token → service principal → Azure CLI; env read through a closure so tests inject it); `resolve_model` takes a portal link, `--workspace`/`--model` names or ids (no workspace: search all, refuse on ambiguity), or the `picker`s. `downstream::discover` + optional `verify`, then `fetch/render.rs` prints the forecast; a non-downloadable model is exit `2`, an incomplete report set prompts on a TTY and is exit `2` otherwise unless `--allow-incomplete`. `fetch/layout.rs` checks the output dir (empty, an earlier fetch of the same model, or `--force`), writes parts through `safe_join` (untrusted paths), skips `StaticResources/`, and writes `ripbi.toml` (marker line; a foreign one is kept) and `.ripbi/source.json` (`Manifest`, also read by `scan` for the `incomplete_report_set` skip notice). `--scan` runs `scan::run_in` from inside the folder. `run_with` injects the `Service` (tests use `ripbi_service::fake`) |
| `stub.rs` | `ripbi stub-report` (issue #130): resolves a `.SemanticModel` (PATH, its `definition/`, or the only one in the cwd), writes `ripbi_core::report_stub` into a fresh temp folder (or `--out`) with a relative `byPath` back to the model (canonical long paths; another drive is exit `2`), prints the `.pbip` path on stdout, opens it in Desktop when interactive on Windows (`should_open`; `--no-open`), and with `--wait` polls `.pbi/cache.abf` until a new save settles (`wait_for_save`). `--out` never overwrites: an existing `.Report`/`.pbip` is exit `2` unless `--force`, and `--force` replaces only a ripbi stub, never a real report. `scan` names stubs in a note and treats a model whose only reports are stubs like one with no reports (refusal, or the `--allow-no-reports` skip) |
| `update.rs` | `ripbi update`: GitHub release lookup (ureq), `sha256sums.txt` verification, tar.gz/zip extraction, channel detection, atomic replacement of `ripbi`/`rib` — the running binary last, and on Windows a locked target (the install scripts hard-link `rib` to `ripbi`) is moved aside to `<name>.old` instead of failing. `ReleaseClient` is the network seam; `run_in_with_home` injects the exe and cargo home |
| `picker.rs` | The one picker: `scan`/`report`/`deps` project discovery and `fetch` workspace → model. Stdin and stderr both TTYs: `dialoguer` fuzzy select drawn on the console (a bare `\r` through `Streams.err` first holds the `progress` ticker off; the echoed choice releases it). Otherwise a numbered list on stderr read with an unbuffered `read_line`, so two prompts share one stdin — the path tests drive. Also `confirm` (`[y/N]`) |
| `notify.rs` | the ambient daily check: XDG/LOCALAPPDATA state file, detached `__update-check` child, the `after_command` notice hook, and env/CI/TTY/`-q` suppression. `NotifyContext` is the test seam |
| `render.rs` | the three output modes: human, `--plain`, `--json` — plus the Auto date/time section rendered in all of them, and the storage sizes of PBIX/`.abf` findings (issue #122: `(1.2 MB)` beside a finding, the `Unused storage:` total that `scan.rs` dedupes by owning table, the plain third field, the optional JSON fields — all absent without a storage catalog, so other inputs render byte-identically; `--sort size` reorders `findings` in `scan.rs`). `GROUPS` is the fixed kind order the type selection prints in; `KINDS` is the machine vocabulary `scan --type` and `deps --type`/`--consumer` validate against (locked to `kind_of` by test). A lone `--broken` uses `No broken reports or artifacts.` when both breakage sections are empty. `ScanOutput::kept` (`DependencyGraph::kept`, issue #151) is the JSON `summary.kept` count only — kept objects are roots, never findings, and the human modes list them nowhere. `Finding.table` (`ObjectId::owning_table`, set in `scan.rs` only for `--json`/`--summary`) feeds the JSON `table` field and `--summary`'s worst-tables breakdown |
| `compare.rs` | `scan --compare-root` fingerprints (issue #141): `Entry` (kind + display id, plus reason/site, report name, or verdict), matched case-folded through `Key` and never by path; `Detected` (the ordered map one scan fills) and `fixed`. `scan.rs` runs the "before" pass as the same `scan` in the other root (`scan_before`: relative flag paths rebased, output silenced, `probe` collects what it detected), fingerprints every finding before its own filters (so a filtered finding is never "fixed"), and drops existing ones after them, counting `existing` |
| `sarif.rs` | `scan --sarif` (issue #142): the SARIF 2.1.0 log. A fixed `RULES` catalogue (ids are the contract, order is `ruleIndex`); a `Locator` that `scan.rs` feeds per finding (the TMDL declaration line from `ripbi_core::ingest::source_locations`, else the model file or the report's `report.json`); fingerprints hashed from `compare::Key`; and `Existing`: under `--compare-root`, `scan.rs` keeps the findings the other modes drop so they render as `external` suppressions. Relative URIs are anchored at the scan's cwd (`%SRCROOT%`) |
| `tx_rm.rs` | `scan --emit tx-rm`: the reported findings plus dead auto date/time tables as JSON Lines for tomix's batch `tx rm --from` — `{type, table?, name, id}` per line (`serde_json`, never hand-built; non-ASCII as `\uXXXX` so the pipe survives PowerShell re-encoding), an unnamed relationship as `{type, path}` in endpoint form, report measures and bookmarks as `# skipped` comments. No ordering: `tx` judges the whole set. Contract: `docs/scan/tx-rm.md` |
| `vso.rs` | `scan --azure-devops`: one `##vso[task.logissue]` line per finding, rendered from `sarif::issues` (the same rule ids, messages, and sites; `sourcepath` is cwd-relative). Drops `--compare-root` existing findings like the non-SARIF modes; escaping follows azure-pipelines-task-lib |
| `markdown.rs` | `scan --markdown-file` (issue #143): the Markdown job summary / PR comment — headline counts (new · fixed · existing under `--compare-root`), per-type totals, the findings and `Fixed since` tables capped at `MAX_ROWS`, and `render::worst_tables`. Rendered from `ScanOutput` alone; ids go through `code`, which escapes pipes for GFM tables\|` for GFM tables. `scan.rs` `write_side_outputs` writes it and the `--sarif-file`/`--json-file` copies (the stdout renderers into a buffer) from the same scan, before stdout and regardless of `-q` |
| `style.rs` | The "pruning shears" ANSI palette, gated on TTY (or `CLICOLOR_FORCE`) / `NO_COLOR` / `TERM=dumb` / `--no-color`. Methods are roles, not colors: `warn` (rust — unused), `ok` (moss — clean), `alert` (brick — errors, breakage), `muted`/`dim` (warm greys — notes, annotations), `accent`, `bold`; `warn_note`/`info_note` draw `scan`'s tiered `  !`/`  ·` stderr notes (every model command reaches them through `scan::Notes` and opens with `scan::pairing_announce`). Truecolor when `COLORTERM`/`WT_SESSION`/`TERM_PROGRAM` says so, else xterm-256. Styling only ever adds color: uncolored text is the output contract. `help_styles()` maps the same inks onto clap's `--help`/usage errors (`cli.rs` `styles = …`; clap gates color itself) |
| `progress.rs` | The stage ticker `scan`, `report`, `deps`, and `fetch` (exports → write, with a `Progress::detail` counter) share on stderr (`◐ discover · model · reports · graph · findings  0.8s`); it clears when the run ends, and each command puts `Progress::elapsed` on its own closing line; each command passes its `Pipeline` (`SCAN`/`REPORT`/`DEPS`: stage names + closing verb). Runs only when stdout and stderr are TTYs, the stderr palette is on, and the mode is human without `-q` (`Progress::wanted`); appears after 120 ms. It starts before `resolve_target`, so the discovery walk is covered, and each command swaps its `Streams.err` for `Progress::writer` for the whole run: every write erases the line first, and a write that leaves a line open (the picker prompt) holds the ticker off. `entry.rs` keeps stderr unlocked so the ticker thread can draw |
| `glob.rs` | case-insensitive `*`/`?` matcher for `[scan].ignore` |
